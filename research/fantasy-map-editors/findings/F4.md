# F4: User pain points and must-have wishlists

## Findings

### [1] Fantasy map editors lose custom label fonts and localized names across version upgrades, so users see English fallback text in a clipped heavy face instead of their styled labels
- quote: "it changed all the other names from polish to english, and did so incorrectly. The font is bad too."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1824
- source_type: community
- published: 2026-09-09
- confidence: high

### [2] v1.140-style label-group migrations can permanently bake transient zoom `display: none` into saved styles, so entire settlement label tiers (hamlet/village/trading post/monastery/fort) never render at any zoom
- quote: "Reported on Discord as \"labels don't show up on my map\". River, route, state and province labels render normally; hamlet, village, trading post, monastery and fort labels never appear at any zoom."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1773
- source_type: community
- published: 2026-09-03
- confidence: high

### [3] Unvalidated localStorage label options silently strip every label from newly generated maps, and users misdiagnose the result as a corrupt .map file
- quote: "A stale or malformed value there silently removes **all labels from every newly generated map**, permanently, for that browser. Nothing in the UI points at the cause, and the user's natural conclusion is that their `.map` file is corrupt."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1771
- source_type: community
- published: 2026-09-03
- confidence: high

### [4] Users want multiple simultaneous legends (states + zones + cultures), and the single-legend toggle currently deletes the existing legend without drawing a replacement
- quote: "Only one Legend box can exist at a time, and turning on a second one silently removes the first without drawing the new one — so you end up with no legend on the map at all."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1815
- source_type: community
- published: 2026-09-08
- confidence: high

### [5] A heightmap legend (elevation scale bar / color ramp) is an open wishlist item so players can estimate heights from a PNG export
- quote: "So you can have a rough guess of how high something is from a png"
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1707
- source_type: community
- published: 2026-09-03
- confidence: medium

### [6] PNG/JPEG export is unreliable even at full-world zoom, producing large black regions in the downloaded image
- quote: "When exporting the map as PNG or JPEG, the resulting image is partially black (large black areas appear on the sides/bottom), regardless of the scale value set in the export dialog."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1882
- source_type: community
- published: 2026-09-17
- confidence: high

### [7] Memory use with many assets and large maps is a hard blocker: Dungeondraft on Linux hit 25+ GB RAM on a 65x90-tile map (~8 MB) and froze the whole OS at ~97% RAM
- quote: "I've noticed my memory usage while Dungeondraft is opened is going through the roof... 25+ GB of RAM is still absurdly high."
- url: https://github.com/Megasploot/Dungeondraft/issues/79
- source_type: community
- published: 2026-01-07
- confidence: high

### [8] Browser-based editors also hit OOM with progress loss (Chrome "Out of Memory" after long sessions, all work lost on refresh), confirming crash-safe autosave/undo as a must-have
- quote: "Randomly getting a Chrome error while working. Says the error is \"Out of Memory\". Upon refreshing, I've lost all my work."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/787
- source_type: community
- published: 2022-04-30
- confidence: high

### [9] Frame rate collapses on strong hardware in web map generators, and users escalate to Reddit before filing bugs
- quote: "For details, I refer back to my Reddit post: https://www.reddit.com/r/FantasyMapGenerator/comments/1cteiv0/is_this_frame_rate_normal/"
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/1075
- source_type: community
- published: 2024-05-17
- confidence: medium

### [10] Custom-asset workflow is a top friction theme: users must stop mid-map to rebuild asset packs for a single PNG, Cartography Assets packs fail to appear in the placement menu, and official wiki lacks add-asset docs
- quote: "As it stands, I have to stop what I'm doing to create a custom asset pack or update my asset pack. It's a complete hassle and breaks the workflow."
- url: https://github.com/Megasploot/Dungeondraft/issues/80
- source_type: community
- published: 2026-01-14
- confidence: high

### [11] Text and path theme styles do not persist into saved themes, forcing manual re-styling when stitching multi-tile world maps (user target: 20,000+ px)
- quote: "Glow for text and colour for paths is not retained when I save themes. I'm trying to maintain consistency across multiple maps that will be stitched together to form a 20 thousand+ pixel resolution world map"
- url: https://github.com/Megasploot/Wonderdraft/issues/34
- source_type: community
- published: 2024-11-19
- confidence: high

### [12] Custom-color assets break under theme changes and custom packs load wrong RGB, so symbols do not recolor with map themes
- quote: "Custom colored assets do not adapt their color when the theme is changed... any new assets I place are colored differently."
- url: https://github.com/Megasploot/Wonderdraft/issues/31
- source_type: community
- published: 2024-05-27
- confidence: high

### [13] Explicit product wishes include copy/paste for assets and text (to keep size/color consistent) and per-tool hotkeys for productivity
- quote: "This is particularly useful for keeping assets and text the same size/color."
- url: https://github.com/Megasploot/Wonderdraft/issues/21
- source_type: community
- published: 2021-11-30
- confidence: medium

### [14] Users request fog-of-war / selective reveal for player-facing maps and a place to share maps and templates (community gallery)
- quote: "Fog of war: I would greatly appreciate the possibility to hide large portions of the maps before printing... I would like for them to not know that the continent other than the one they live on even exists until it's time to reveal it's existence in game."
- url: https://github.com/Azgaar/Fantasy-Map-Generator/issues/88
- source_type: community
- published: 2018-06-24
- confidence: medium

### [15] Batch/headless export is requested so users can convert many downloaded maps to PNG without opening each file
- quote: "I want to be able to batch export dungeons that I have downloaded to PNG but it takes a while to open one by one to export. It would be nice to pass the dungeondraft maps and settings to a CLI tool"
- url: https://github.com/Megasploot/Dungeondraft/issues/81
- source_type: community
- published: 2026-02-25
- confidence: medium

## Dead ends
- Bing/Google/DuckDuckGo/Mojeek/Brave/Startpage/Yandex/Ecosia search endpoints either timed out, 403'd, or (Bing CN) returned fantasy-football noise instead of map-editor results
- Reddit (www + old + search) transport-errored; could not fetch r/rpgmapmaking or r/wonderdraft threads directly
- Steam store and steamcommunity review endpoints timed out
- Inkarnate changelog is a JS SPA ("You need to enable JavaScript") and yielded no static changelog/wishlist text
- Cartographers' Guild homepage is reachable but forum content is login-gated
- GitHub search for "inkarnate" issues returned 0; Inkarnate has no public issue tracker with user complaints

- Compare Inkarnate public roadmap / help-center "feature request" posts against these GitHub-derived themes
- Quantify performance complaints (many symbols/labels/paths) with concrete object-count thresholds from Steam negative reviews
