# 地图编辑器数据模型思考记录（终版）

> 这不是设计指南，是对一段讨论中我自己思路的忠实整理。
> 记录我在设计一个以"地块"为基本单元的架空世界地图编辑器时，是怎么一步步把数据模型想清楚的。

---

## 0. 缘起

从一张 Voronoi 风格的架空大陆高度图开始。先做了一件很具体的事：从高度图提取色阶（深海→近海→滩涂→平原→丘陵→高山），想转成 CSS 渐变。
但真正的兴趣很快转向：**对着这张地图，人文信息该怎么分层去看、怎么去存。**

---

## 1. 人文三要素在地图上的关系

最初的疑问：研究地图时，文化和宗教可以放一起吗？

判断：**可以放一起，但不能画等号。** 大尺度上宗教是文化的子集，打包成文化圈看没问题；落到细节就会错位——同文化不同教、同教不同文化、有文化无成熟宗教。

加入种族后，形成第一个硬结论：

> **种族、文化、宗教三者之间不存在天然的父子（包含）关系，它们是三个互相独立、可以交叉也可以错位的维度。**

- 种族 = 血脉/起源/体质，"从哪里来"，难短期同化；
- 文化 = 后天习得的生活方式，"怎么活"，几代人就能换；
- 宗教 = 文化里的精神分支，"信什么"，能随文化走，也能单独跨文化传播。

如果世界观里"一种族=一文化=一宗教"，地图会非常扁平；张力全部来自三条线互相切割。

### 图层怎么摆
- 主图层：文化；子图层：宗教（本地化后的教派）。
- 种族**不能**挂在文化下做子图层——它是交叉分布，不是包含关系，必须平行独立。

### 跨文化宗教的破局
文化→宗教的父子结构会被普世宗教"溢出"边界打破。想通的一件事：

> "跨文化的宗教其实本身也不一样了，可以被细分。"

从起源看是同一个母教（月神礼制派/月神风暴派，源头都是月神）；落到地图上，它们已经完成本地化（仪式、教义侧重、神职体系、吸收旧神）。一旦本地化，它就**不再是母教的一块溢出色块，而是所在文化圈自己的教派**。

- 地图图层里：每个本地化教派各自挂在自己的文化下；
- "同源"不画在地图上，记在设定文档里。
- 叙事红利：同源教派之间反而可能互相视为异端。

---

## 2. 图层清单的成型

第一版完整清单：

> 地块、高度、国家、行省（国家子图层）、种族、生态、文化、宗教（文化子图层）

结构判断：
- 行政体系做父子：国家→行省，这是真·包含关系；
- 文化→本地化教派：前述简化结构；
- 种族、生态：平行图层；
- 地块、高度在最底层做物理基底。

后来补过一批候选：水文、资源、聚落、交通路网、语言、历史边界、争议区、圣地、游牧区……
自己给自己立的规矩：**不要无脑堆面图层。** 色块越多越乱，新增信息优先做成点、线图层。

---

## 3. 地块是最小单元

讨论军队、家族是不是图层时，引入了关键底层概念：

> **地块是我这个地图的最基本单元。**

这句话一出，讨论从"手绘色块地图"变成了"以地块为最小单元的地图编辑器"。所有图层本质上都围绕地块组织。

---

## 4. 反对模拟器式的"实体/属性"二分

讨论中对方一度把东西分成两类：地块固有属性（高度、文化、归属），和独立实体（军队、家族，说它们"不属于地块、可以移动"）。

我直接否了这套切法：

> "你的抽象能力很差。这些东西不全都是地块属性吗？在数据结构上能有什么不同？"

核心立场：**用"会不会自己移动、灭不灭亡"来切分类，那是游戏模拟器的思路，不是地图编辑器的思路。** 地图编辑器不需要自动推演，那些"实体生命周期"的代价对我根本不是代价。

---

## 5. 元素与地块双向引用

给出的答案非常干脆：

> "元素和地块是互相引用的——地块只保存自己被什么元素占据，元素保存自己占据了哪些地块。"

```
地块  ──持有──>  关联的元素 ID 集合
元素  ──持有──>  关联的地块 ID 集合
```

双向外键，两边各存一份，增删时两边同步。

---

## 6. 所有属性都是元素，图层只是视图过滤器

顺着双向引用，把最后一层抽象拆掉：

- 底层一个 Element 基类，所有东西都是它的实例；
- 区分元素靠**元素的 type** 和**元素自身的元数据**；
- **图层根本不是独立的数据类，它只是一个视图过滤器**：按 type 筛一遍元素，把它们关联的地块画出来。

这正是地图编辑器想要的：一套底层接口通吃所有元素——刷地块、解绑、复制、删除、撤销重做、快照、导出全部复用。想加新图层（疫病区、魔法领域、语言区……），只要加一个 type，不动底层模型。

### 明确不要：关联角色标记
曾有人提议在元素↔地块的引用上加角色（LAND_ATTRIBUTE/OCCUPY/CLAIM）来区分"固有属性/驻扎/宣称"。
我反对：

> 地图编辑器没必要带角色。各种元素占据地块，自然有相应的占据方式，不必做一次区分，因为没有意义。

占据的语义由元素的 type 和元数据承载，引用链路上加角色标记是多余设计。

---

## 7. 高程区间元素：派生关系要实体化

高程这里一直觉得别扭：别的元素是"一块地绑一个元素"，而高程是**区间聚合**——1–3 是浅滩，4–10 是低地，10–16 是平原。它不是人手刷出来的，是根据地块 height 自动归堆的。如果让它维护一份"我关联了哪些地块"，这份关系就是间接派生的，和国家文化那种人工刷出来的关系性质不同——这就是别扭感的来源。

提出的解法是把派生关系**实体化、落盘化**：

> 高程元素在生成/绘制时通过高度计算，生成完成后，数据里保存的其实就是和地块的直接双向关系。

- 高程分区是一种**批量生成**出来的普通元素；
- 生成那一刻按高度区间跑一遍规则，把结果写成与地块的双向关联，存进存档；
- 存完之后，它和国家、文化在数据结构上**没有任何区别**；
- 差别只在 parcelLinks 怎么来：国家是人手刷的，高程分区是规则批量算的；
- 改地块高度后标"脏"标记，提示重新生成；
- 生成之后**允许人工微调边界**——架空地图里"理论上这高度该是平原，但设定上这里是特殊洼地"是真实需求。

好处：模型彻底统一，不存在"动态派生元素"这种特殊分支。代价（改高度要手动刷新）对编辑器完全可接受，因为编辑本来就是分阶段的：先刷地形→一键生成分区→再人工微调。

---

## 8. 约束的本质：图层之间的空间关系，不是谓词读数值

图层不是随便画的，元素有依赖关系。曾考虑过两类约束：
- 对地块原生数值的谓词（高度>0）；
- 元素之间的父子容器（行省必须在国家内）。

后来想通：**不应该用谓词读地块数值那套**。约束应该全部表达成**图层与图层之间的空间关系**，在图层层面可视化配置，不写代码、不写表达式、不解析自定义谓词。

---

## 9. 空间受限关系：统一的核心机制（含反受限）

这是整个模型的核心。图层之间只定义这一种基础空间关系：

> **图层 A 受限于图层 B**

配置项：
1. **集合判定方式**：被包含 / 互斥 / 相交 / 超集 / 等价。
2. **数量范围**：最少 Min 个、最多 Max 个 B 元素（A 元素与 B 图层元素之间满足该集合关系的数量）。Min 可以为 0。
3. **反受限开关（布尔）**：
   - 关闭（单向受限）：仅在 A 绑定地块时校验 A 是否符合条件；A 的改动**不改变 B 的空间**。
   - 开启（反受限，双向联动）：A 的改动**触发 B 的空间重算**——B 元素的空间 = 所有与它满足该受限关系的 A 元素的地块并集。

### 关键修正：重叠即争议区
曾错误地说过"几何重叠但归属独立、不触发聚合"。这是错的。正确理解是：

> 受限关系一旦定义为「A 被 [B 的至多 N 个元素的集合] 包含」，那么 A 就**同时属于那 N 个 B 元素**。
> 地图编辑器只是把这种多归属**标识为争议区域**而已。

不是"几何重叠但归属独立"——只要关系成立，A 就真实地同时属于那几个 B 元素，重叠本身就是争议区的来源，编辑器负责把它画出来、标出来。

### 父子只是这个机制的一个特例
当满足：集合判定=被包含，Min=0，Max=1，反受限=开启——这就是原来的"父子图层"：
- 行省受限于国家；
- 一个行省最多被 1 个国家包含；
- 国家的疆域 = 所有包含它的行省的地块合并；
- 画行省地块，国家自动重算疆域。

**父子不是独立的关系类型，它只是"空间受限"这一种关系的一组特定参数。**

### 游离子元素 = Min=0
游离行省不需要额外概念。Min=0 意味着一个行省可以被 0 个国家包含——它照常绑定地块，只是不被任何国家聚合进疆域。游离是参数的合法取值分支，不是特例。

### 父元素可以直接持有地块
旧规则"父图层元素不能直接绑定地块"被推翻。任何图层的任何元素，空间都由两类来源构成：
1. 引用其他图层的元素（来自受限+反受限的聚合）；
2. **直接绑定的地块**。

例子：国家的疆域 = 被它包含的行省地块 ∪ 它自己直接绑定的无人区/无行政地块。国家可以拥有无行政地区或无人区。

### 多层嵌套与多子图层
- 一个父可以同时有多个子图层（如"文明"的子图层是"文化领地"和"城邦"）；
- 支持多层嵌套：联盟→国家→行省→地块；
- 多层反受限逐级向上聚合。

---

## 10. 每次编辑触发全局重计算

只要 A 受限于 B（尤其反受限开启），**任何一次编辑操作（增删地块、改元素关联）都应该对所有相关图层做一次重新计算**，而不是只改当前图层。

反受限开启后必须明确的语义边界：
- A 的元素同时属于那 N 个 B 元素，重叠处标识为争议区；
- 反受限只聚合**满足该条受限关系**的 A 元素；
- 多层反受限逐级向上传递；
- 编辑器检测循环受限（A 受限 B 且 B 受限 A 且都反受限）并标记冲突警告。

---

## 11. 快速配置列表 + 自定义

父子只是一组参数，不该是写死的概念。应该提供一个**快速配置列表**，预设常用的受限参数组合，一键套用：
- "父子从属"：被包含，Min=0，Max=1，反受限开启；
- "多归属行政"：被包含，Min=0，Max=N，反受限开启（行省可同时属多国=争议区）；
- "单向地形门槛"：被包含，Min=1，Max=N，反受限关闭（宗教只能画在陆地上）；
- 等等……

列表可以继续扩展，并且**允许用户自定义参数组合**，保存为自己的模板。

---

## 12. 保留的辅助概念

### 约束继承
图层 B 继承图层 A 的整套空间受限配置，一次性复用全部参数，减少重复配置。适合批量创建同基底约束的人文图层。

### 图层内元素允许重叠（图层属性开关）
布尔开关，控制同一图层内多个元素是否可以共享地块：
- 开启：文化、宗教、争议区——表达交融、争议领土；
- 关闭：行省——一个地块只能属于一个行省。

这是**图层自身属性**，不是图层之间的关系。

### 核心子元素列表（元素内部属性）
每个元素携带一个引用列表，标记逻辑上的关键代表，**不参与空间聚合计算**：
- 国家的核心子元素 = [首府行省]；
- 联盟的核心子元素 = [主持国1，主持国2]。

区别于聚合用的从属子元素：核心子元素只用于编辑时高亮、筛选、渲染，不改变任何疆域。

---

## 13. 被明确剔除的概念

以下都讨论过，但对地图编辑/渲染没有实质价值，舍弃：
- **同源谱系关系**（教派/王朝源流）——不影响空间，不需要；
- **依赖引用**（宗主-藩属那种"引用但不合并空间"）——用联盟图层+反受限+核心子元素就能表达，独立成关系反而增加概念负担；
- **拾取优先/渲染覆盖**——纯画布绘制顺序，是视图层的事，不是数据模型；
- **替代图层**（同元素多视图切换）——视图层功能；
- **属性联动/标签同步**——只同步元数据，不影响地块和空间；
- **关联角色标记**（LAND_ATTRIBUTE/OCCUPY/CLAIM）——多余，语义由 type 承载。

---

## 14. 一页纸核心立场

1. 文化做主图层、宗教做本地化教派子图层；种族是平行交叉维度，不做任何图层的子图层。
2. 跨文化宗教按文化拆成本地化教派，同源记在设定文档，不画在地图上。
3. **最小编辑单元是地块**，所有图层都是地块上的投影。
4. 反对用"会不会动、灭不灭"切数据类——那是模拟器思维。
5. **元素与地块双向引用**，不加角色标记。
6. **所有属性都是元素，统一一个基类**；图层只是按 type 过滤的视图。
7. 派生关系（高程分区）生成那一刻就实体化为双向关联存盘，之后当普通元素对待，不留"动态派生"特殊分支。
8. **约束统一为"空间受限"一种机制**：集合判定（被包含/互斥/相交/超集/等价）+ Min/Max 数量 + 反受限开关。不写谓词、不读地块数值。
9. **父子只是空间受限的一组特定参数**（被包含、Min=0、Max=1、反受限开），通过快速配置列表提供，且支持用户自定义。
10. 反受限成立时，A 真实地同时属于那 N 个 B 元素，重叠处就是争议区，由编辑器标识。
11. 父元素可以直接持有地块（无人区）；游离元素 = Min=0。
12. 任何编辑操作触发相关图层全局重计算。
13. 配套只保留：约束继承、图层内允许重叠开关、元素的核心子元素列表（不聚合空间）。
14. 视图层的事（渲染顺序、多视图切换、标签同步）不进数据模型。
