## 2. 架构评价

**优点**

- Core / UI / Render / Persist 分层清晰  
- `EditorStore` 集中可变状态；chrome/workbench 组件化  
- 索引（CellGrid / RegionIndex / CellGraph）+ History + 生成注册表齐全  
- Worker 生成 + Three 懒加载，首包约 56KB gzip  

**风险**

1. **球面 Voronoi 成本**：25k 蓝噪声 + 外心约数秒（Worker 内可接受，主线程回退会卡）  
2. **邻接**：外心法 + kNN 过滤，少数 cell 可能邻接不完整 → 影响河流/道路连通，靠校验器兜底  
3. **投影极区**：Mercator 钳制 lat，极区 2D 仍扁；球面视图正确  
4. **序列化**：25k JSON ~12MB；gz 可用但未强制  
5. **World 对象拷贝** `touchWorld` 整引用替换，大地图浅拷贝 regions 数组仍可能让 derived 变贵

## 3. 性能摘要

| 指标 | 约值 |
|------|------|
| 25k 全管线（含蓝噪声球面） | ~3–4.5s（测试环境） |
| 12k | ~1.4s |
| 主 JS gzip | ~56KB |
| 笔刷 | 网格半径查询，非全表 |

建议实机：25k 下测 FPS；若不足，优先 offscreen 分层重绘，而非立刻 WASM。

## 6. 结论

优化主干（索引、生成协议、撤销、UI/渲染分层、球面拓扑）**已落地**，与需求文档对齐度高。当前更像「可继续打磨的编辑器骨架」，而非未完成的原型。下一阶段建议以 **实机交互质量**（FPS、邻接、极区 2D）为主，而不是再扩功能面。
