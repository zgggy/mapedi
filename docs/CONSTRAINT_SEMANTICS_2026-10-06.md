## 1. 统一语言（北极星 §9 原样）

> **图层 A 受限于图层 B** = ①集合判定方式（被包含 / 互斥 / 相交 / 超集 / 等价）
> ＋ ②数量范围（Min / Max 个 B 元素）＋ ③反受限开关（关=单向受限；开=双向联动，B 的空间
> = 所有满足该关系的 A 元素地块并集）。**父子只是这组参数的一个特例**（被包含，Min=0，
> Max=1，反受限开）；**游离 = Min=0 的合法分支**，不是特例；**重叠即争议区**——关系成立时
> A 真实地同时属于那 N 个 B，编辑器负责把它标出来。

## 3. 「父元素可直接持有地块」核实（§9 vs AGENTS §3）

- 现状：`materializeParentCells` 对每个有子的父**从空重建** `cells = ∪子`
  （`displayCompose.ts:128-140`），父自己绑定的地块被丢弃；AGENTS §3 明文
  「父 `cells` 必须已物化子并集；禁止运行时第二套 union」。
- 北极星 §9：父空间 = ∪被包含子 ∪ **自持地块**（无人区/无行政地）。
- 两案：
  - **A（维持现状，推荐 v1）**：父 ≡ ∪子。干净、物化单源、无「自持+子」双来源歧义。
    「无人区」如需表达 → 用独立图层/元素承载（当前已可）。
  - **B（对齐北极星）**：父 `cells` = ∪子 ∪ 自持——自持部分必须**独立存储**
    （如 `Region.ownCells?: CellId[]`），否则下次物化必被吃掉；渲染/校验/删除策略全链感知
    （估：物化与策略链 12+ 处）。

## 5. 冲突点登记

1. **父 ≡ ∪子（AGENTS §3）** vs 北极星 §9「父可直接持有地块」→ §3 两案，待拍板。
2. **每层 ≤1 子**（`gate.ts:32-36`）vs 北极星 §9「一个父可多子图层」→ 需 layer tree 由链改树
   （缩进/提升/`layerDisplayList`/`childLayerIdOf` 全链）；登记立项条件。
3. 北极星 §10「每次编辑全局重算」vs 项目红线「定向失效+增量」→ **已裁定**：以 cause→touch
   表（包 F）保证同语义，不引入全局重算。
4. `PlacementRule`（读数值谓词）vs §8「约束不读数值」→ 建议改「单向地形门槛」受限表达；
   门槛目标 = 高度层（内置）或包 D 派生陆海层（用户例正好是它）。
5. `require*`（现仅校验）是否前移为**写入闸**（包 C `setOccupyGuard` 预留的拒名单闸）——
   决定权在用户；前移会改变「画了才报错」为「画不上」。

## 6. 结论

- 本包交付 = 本快照 + 统一语言映射表（§2）+ 手册包 E 分析。**代码零改动、字段零改名。**
- 待拍板清单（逐条给建议）：① 多归属做不做（建议 v1 不做）；② 父自持两案（建议 A：维持 ≡∪子）；
  ③ 单向地形门槛改造时机（建议：做，作为受限概念的第一个真落地——与包 D 派生层衔接）；
  ④ `require*` 前移（建议：暂不，等有真实误画反馈）；⑤ 多子图层（建议：登记，暂不做）。
